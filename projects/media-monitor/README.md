# Сборщик мониторинга СМИ

Работает без API модели. Не требует расширения Chrome для обработки файлов.
Нужен Python 3.9 или новее. Для JSON, HTML, TXT и DOCX дополнительные пакеты не нужны.
Для PDF: `python3 -m pip install pypdf`. Сканированные PDF требуют отдельного OCR.

## Проверенный запуск

В папке проекта открой терминал VS Code и выполни:

```sh
python3 monitor.py --start 2026-10-26T11:00:00+03:00 --end 2026-10-27T11:00:00+03:00
```

Начало включается, окончание не включается. Часовой пояс обязателен.
Результат: `results/results.json` с текстами, происхождением данных, цитатами,
ошибками и спорными датами; `results/report.md` — короткий обзор.
Скрипт без параметров обрабатывает все импортированные даты.

В `inbox/kommersant_live.json` находится реальная статья от 27.10.2026,
полученная через разрешённый браузерный инструмент. Это проверка работы на
реальных данных, а не полный мониторинг. Из текста подтверждены NF GROUP,
Nikoliers и комментарий Евгении Хакбердиевой. Сегмент эксперта не додуман.

## Новые материалы

Положи в inbox сохранённые тобой статьи JSON, HTML, TXT, MD, DOCX или PDF.
Для TXT/PDF/DOCX создай рядом файл `article.txt.meta.json` (расширение исходного
файла остаётся), например:

```json
{
  "publisher": "Название издания",
  "title": "Дословный заголовок",
  "canonical_url": "https://example.org/article",
  "published_at": "2026-10-27T08:30:00+03:00",
  "publication_timezone": "Europe/Moscow",
  "body_scope": "article",
  "source_reviewed": false
}
```

`source_reviewed: true` ставится только после проверки, что сохранённый текст
действительно является текстом нужной статьи. Само наличие HTML/PDF этого
не доказывает. Статус `body_mentions_confirmed` подтверждает упоминания в
полученном тексте, но не гарантирует полноту статьи или всего мониторинга.

Для спикеров можно добавить массив `speakers` с полями `name`, `company`,
`evidence`. Программа принимает имя только при наличии имени и всей
подтверждающей цитаты в тексте. Связь должности, компании и сегмента
окончательно проверяет редактор. Программа её не выводит из темы статьи.

У HTML извлекаются только видимые текстовые узлы; script/JSON-LD не используется
как способ получить скрытый или закрытый текст. Если нет article, результат
помечается для проверки: навигация и другие блоки могут дать ложные совпадения.

## RSS

Поддерживается загрузка проверенных официальных RSS/Atom. Пример записи в
`sources.json` (пример не является реальным адресом):

```json
{
  "feeds": [{
    "publisher": "Издание",
    "url": "https://example.org/feed.xml",
    "approved_hosts": ["example.org"],
    "official_endpoint_verified": true,
    "enabled": true
  }]
}
```

Указывать `official_endpoint_verified` можно только после фактической проверки.
В поставке нет подтверждённых RSS, поэтому список пуст. Сеть из текущей среды
для RSS не тестировалась. RSS хранит только кандидатов: его краткий текст
не становится подтверждённой статьёй. Перенаправления проверяются по тем же
разрешённым доменам; домены с явным запретом инструмента не запрашиваются.
Нет прокси, маскировки местоположения, обхода CAPTCHA, paywall или входа.

## Проверка

```sh
python3 -m unittest -v test_monitor.py
```

Проверены совпадения компаний и исключение обычного Метриума, даты с часовыми
поясами, отсечение текста навигации и script, непроверенные RSS, неподтверждённые
имена спикеров, запреты доменов, дубли, повреждённый файл и границы окна.
PDF/DOCX импорт реализован, но на реальных статьях в этом запуске не проверен.

Нельзя считать выпуск полным: поиск по всем источникам, тематические рубрики,
Яндекс/Дзен и сверка со вчерашним выпуском этим тестом не выполнены.
Автоматическая группировка перепечаток по смыслу и особые правила повторов
петербургского блока ещё не реализованы; URL-дубли убираются внутри текущего сбора.
